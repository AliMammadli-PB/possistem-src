## Operating the assistant

Admin → Dəstək idarəetməsi → **Köməkçi · Təlimlər**. Add a topic, language, scope, example questions/alternative spellings and the correct answer. Save the draft, check the answer with the preview, then publish. Preview uses no customer identity and sends no till operation. Reports can prefill a draft from the question preceding the badly rated response; a report never publishes itself. Publish history shows the author and timestamp. Restoring an older revision publishes a new immutable revision. Simultaneous draft edits are checked by draft version.

The website and Restaurant POS use `/customer/assistant/v1/{sessions,message,result}` under `/pos/api`. Published training is read on the next message of an open session. The legacy website `/customer/assistant/reply` remains compatible and also reads published informational training. No external language-model provider is configured.

The desktop requires this one-time connector release. Afterwards, informational training is changed in the admin panel, while language routing and existing workflow logic are deployed on the API. New native/device capabilities or desktop UI changes can still require an installer. Market POS and Android are outside this release.

## Ownership and security

- The server owns interpretation, fuzzy product matching, multi-step stock/product/recipe drafts and conversation state. Canonical workflows are in `platform/apps/api/src/lib/assistant/runtime/`; application compatibility exports exist for QA only. Production renderer assembly bundles `support/online.mjs` and fixed local tools, without the old conversation engine or website knowledge fallback.
- Main process `support/online-client.cjs` obtains the existing tenant credential, device and native staff identity. It sends bearer credentials in headers only and binds responses to the same owner/device/staff/permission scope. Renderer IPC is registered by the durable owner assembly patch.
- Native actions use an explicit tool allowlist and require the same previously displayed approval before a write. Quantity/version comparisons, native permissions, idempotency and native audits remain in force. Chat/training text never becomes JavaScript, SQL or an arbitrary IPC method. Card/PIN/password credentials are not part of the tool payloads; complete SQLite backups are not sent.
- The server persists an opaque-secret hash, owner/device/staff scope, current workflow and tool continuation. A completed request cannot be reused to approve a later draft. Current-turn tool results are replayed after a restart without re-running historical writes. Knowledge revision changes before confirmation require a fresh preview. Core capabilities remain versioned at protocol 1.
- Assistant sessions expire after 24 hours; new session creation cleans up at most 200 expired sessions. Business data, legacy support reports and accounting records are untouched by this cleanup.
- Assistant connectivity is online-only. No offline operation queue or bundled-answer fallback is used. A lost write acknowledgement is reported as uncertain and is not retried automatically. The POS itself retains normal offline operation.

### API hotfix — full native role permissions (2026-11-07)

The installed main-process connector submits the whole native administrator permission catalogue (currently 65 entries), while the initial API accepted at most 40 entries. That rejected session creation before the user's `sa` message was processed. The bounded transport limit is now 1024; duplicates and unsupported permission names are removed before persisting the eight assistant-relevant capabilities. Native authorisation remains unchanged.

Regression coverage invokes both the main-process source and the actual CJS extracted from the 1.10.21 app.asar through the real Fastify routes, using the complete 65-key catalogue. Session creation and `sa` both pass; unknown permission keys do not enter assistant capabilities. The anonymous live probe now reaches the expected 401 authentication gate instead of a validation error; live site `sa` receives a greeting. API build and three route/connector checks passed. This is an API-only fix: no new installer, application version or device rebuild. Previous compiled route: `/opt/possistem-pos-control/backups/assistant-permissions-20261107/assistant-central.js`.

# Restaurant POS 1.9.19 — one PIN input and current Linux desktop launcher

This patch includes the 1.9.18 USB backup work and all 1.9.17 branch/subscription/Xprinter fixes.

The old “possistem NEWEST” desktop shortcut pointed to the legacy root restaurant folder, so new builds in the release worktree did not reach that shortcut. `npm run install:newest-shortcut` now points `~/Desktop/Possistem-Newest/current` at the tested runtime, backs up its previous launcher/desktop entry and records the version. Rebuilding on every click is disabled. Explicit development rebuilds use fail-closed assembly.

The login screen uses one masked numeric input with a maximum of ten digits. There is no visible local/platform mode switch, default PIN, administrator digit-count hint or digit counter. Completing ten digits submits once without waiting for prefix lookup. Local four-digit PINs still auto-submit when the signed prefix lookup excludes a platform prefix. Enter provides the four-digit fallback for a colliding/unavailable prefix, without a separate mode button. Mandatory local PIN change still asks for confirmation. Failed/unavailable prefix lookup does not show a premature login error; only an actual authentication attempt does. Subscription enforcement remains in the renderer/main/native boundaries.

Checks: typecheck, all 102 assembly patches, actual renderer single-input/keyboard/touch/paste/invalid-digit handling, full ten-digit entry with successful/failed/delayed/unavailable prefix, four-digit login and mandatory change, and layout at 390/768/1366/1920. The existing Vitest suite remains at 24 failed / 273 passed; those failures are not reported as resolved by this UI patch. Packaged dependency, Electron IPC and native results are recorded with the build artifacts.

Local database copies were created with SQLite's online backup API before switching the desktop launcher. No customer's PIN, password, paid period or account identity is reset. The installer remains unsigned until a Windows signing certificate is configured; no stable automatic update feed is changed by this patch.

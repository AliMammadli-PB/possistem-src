This patch fixes the reported `lahmacun` confirmation failure and the recipe catalogue crash. It does not add an external AI provider or move conversation rules back into the application.

## Changes

- PostgreSQL JSONB reorders object keys. Server tasks, approvals and continuation digests now use a canonical JSON representation. Installed 1.10.21 clients using exact JSON comparison can accept newly previewed raw-material/stock plans. Pending pre-fix approvals are re-previewed, never silently executed. The new connector compares JSON structures independently of object insertion order while still rejecting changed values.
- The actual Electron preload exposes `pos.products`, not `pos.catalog`. The fixed native adapter uses the real namespace, with a compatibility fallback for existing server adapters. Recipe/menu creation therefore needs this connector patch. Conversation interpretation remains on the API.
- The result endpoint strictly separates `{value: ...}` and `{error: ...}`. An error is no longer stripped by Zod into an empty success result. Missing, ambiguous or empty error outcomes are rejected. Missing catalogue data is reported without an undefined `products` exception.
- Generic requests such as `yeni kalkulasiya mehsulu yarat mene` ask which dish to use; the word `yeni` is not treated as a dish name. Ingredients and quantities are selected by the user, never invented.
- `yeni masa yarat` and `zal adinda masa yarat mene` use a guided area/name/seat-count draft. The fixed local `setupCreateTable` tool needs `tables.layout`, the identical approved plan and current native permission. It checks the area, duplicate name and stable ID, reads back the created table and never creates an area implicitly. Older connectors explain the requirement and the existing Table management path. Portal remote-write allowlists and administrator execution identities were not expanded.

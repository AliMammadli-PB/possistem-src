# Restaurant POS 1.9.23 / Market POS 1.5.78 — Xprinter search without the SDK

On a real Windows till 1.9.22 answered "Xprinter tapılmadı" while "Printerin adı → Axtar" found the
same printer at tcp:192.168.100.176:9100. The search and the change no longer go through
`printer.sdk.dll`; the core speaks the printer's own protocol (read from the SDK and the device):

- Search: "XP0001FIND" to UDP 9000, from local port 9600 (the printer always answers on 9600),
  as unicast to every host of this PC's subnets (up to /22) and as limited + directed broadcasts,
  repeated every 700 ms for 4 s (a real printer skipped about one request in three).
  Reply: "XP0001FOUND" + MAC, 22 00, IP, mask, gateway, 8C 23, DHCP. A unicast reply returns on the
  flow the request opened, so Windows Firewall admits it even without the installer rule.
- Change: "XP0001SAVE" + MAC, 22 00, IP, mask, gateway, 8C 23, 00 by broadcast and to the old IP,
  then read back for up to 10 s.
- Windows: SIO_UDP_CONNRESET is turned off so ICMP port-unreachable from swept hosts cannot abort
  the receive loop. A busy UDP 9600 gives a clear error.

The DLL still ships (package verification checks it) but nothing loads it.

## Verification (real Ethernet Xprinter, MAC 00:61:C6:FA:C1:F3)
- Linux native: 10/10 searches found it; a change re-applied and was read back as verified.
- Windows build under Wine with no DLL and no hosts workaround: 5/5 searches, change verified.
- The printer was left at 192.168.30.176 / gw 192.168.30.1 at the owner's request, to test the
  "Kompüterin şəbəkəsinə uyğunlaşdır" flow on Windows.
- Not exercised: a real Windows till with this build.
